# media-masker

Сервис маскирования фото и PDF перед отправкой модели. Работает локально, наружу ничего не
ходит. Клиент - `pii-proxy` (политика `PII_PROXY_IMAGE_POLICY=mask`).

- Фото: перекодирование (EXIF, XMP, ICC и текстовые чанки не переносятся), OCR Tesseract
  (`rus+eng`) со словами и координатами, детектор ПДн из пакета `pseudonymizer`
  (`PiiDetector.detect`), закраска чёрным слов, пересекающих находку, пикселизация лиц
  (каскады Хаара OpenCV).
- PDF: есть текстовый слой - страница отдаётся текстом (прокси превращает его в text-блоки,
  которые маскирует pseudonymizer токенами); нет - страница растрируется (180 dpi) и
  проходит тот же путь, что фото.
- Распознанное отдаётся и наружу: текст картинки (строки в порядке чтения), содержимое QR и
  штрихкодов, признак «есть скрытый нераспознанный текст». Это настоящие значения, сервис
  локальный; ПДн в них заменяет прокси токенами (`pii-proxy/README.md`).
- QR и штрихкоды находятся и расшифровываются локально средствами OpenCV, область закрашивается
  всегда; рукописные и нераспознанные области закрашиваются эвристикой.
- Сбой любого шага - код 4xx/5xx; прокси такой блок не отправляет (fail closed).

## Запуск

```bash
python3.12 -m venv .venv
.venv/bin/pip install -e ../pseudonymizer -e ".[dev]"
export MEDIA_MASKER_API_TOKEN="$(.venv/bin/python -c 'import secrets; print(secrets.token_urlsafe(32))')"
.venv/bin/python -m media_masker          # 127.0.0.1:8320
.venv/bin/python -m pytest -q             # тесты (нужен tesseract, иначе пропускаются)
```

Без токена и без работающего Tesseract (с `rus` и `eng`) сервис не стартует (код выхода 1).

### Tesseract

Прод (делает оператор): `sudo apt-get install tesseract-ocr tesseract-ocr-rus
tesseract-ocr-eng tesseract-ocr-osd`. Пути по умолчанию подходят.

Без sudo (разработка, замеры 04.11.2026): `apt-get download tesseract-ocr tesseract-ocr-rus
tesseract-ocr-eng tesseract-ocr-osd libtesseract5 liblept5 libgif7 libwebpmux3 libopenjp2-7`,
каждый .deb распаковать `dpkg -x <deb> ~/.local/opt/tesseract/root` и запускать с
```bash
T=~/.local/opt/tesseract/root
export LD_LIBRARY_PATH=$T/usr/lib/x86_64-linux-gnu
export TESSDATA_PREFIX=$T/usr/share/tesseract-ocr/5/tessdata
export MEDIA_MASKER_TESSERACT_CMD=$T/usr/bin/tesseract
```

OpenCV закреплён `<5`: в 5.x пакет headless не содержит каскадов лиц.

## Аутентификация

`POST /mask_image` и `POST /extract_document` требуют `Authorization: Bearer <токен>`
(`MEDIA_MASKER_API_TOKEN`); проверка и предел тела идут до разбора тела
(`BodyGuardMiddleware` из pseudonymizer). `GET /health` без токена.

## API

`POST /mask_image` `{media_type, data(base64)}` -> `{media_type, data, stats, recognized}`.
`media_type` ответа: `image/jpeg` для JPEG, иначе `image/png` (GIF и WebP перекодируются в PNG,
анимация сводится к первому кадру). `stats`: `{words, masked_boxes, faces, low_conf_boxes,
codes, unreadable_boxes}` - только числа.

`recognized`: `{text, codes: [{kind: "qr"|"barcode", text}], hidden_text}`.
`text` - слова первого прохода OCR до закраски, в порядке чтения (слова с уверенностью < 40,
которые на картинке закрашены, в текст не попадают). `codes[].text` - расшифровка; пусто, если
код найден, но не расшифрован. vCard и MECARD разбираются по полям с подписями
(`ФИО: …; Телефон: …; Эл. почта: …; Адрес: …`), иначе `N:Иванов;Пётр;;;` детектор имён не
видит; из Wi-Fi-кода пароль и имя сети убираются. `hidden_text` - закрашена нераспознанная
область (эвристика) или слова с низкой уверенностью.

`POST /extract_document` `{media_type: "application/pdf", data}` ->
`{kind: "text"|"images"|"mixed", pages: [{index, text|null, image|null, recognized|null}], stats}`
(`recognized` - как в `/mask_image`, для страниц-растров).
Решение по каждой странице: >= 20 значимых символов текстового слоя - `text`, иначе `image`
(JPEG, замаскированный). Картинки внутри страницы с текстовым слоем модели не уходят (только
текст). Отличие от первоначального наброска: единый список страниц вместо двух форм ответа,
потому что PDF бывает смешанным.

Коды отказа (тело `{"error": "<код>"}`): 401; 413 (`file_too_large`, `image_too_many_pixels`,
`pdf_too_many_pages`); 422 (`image_undecodable`, `bad_base64`, `empty_file`, `pdf_unreadable`,
`unsupported_media_type`, `pii_remains_after_masking`); 500 (`ocr_failed`, `detector_failed`,
`face_detection_failed`, `code_detection_failed`, `unreadable_scan_failed`, `internal`).

## Как закрашивается

1. Лица (Хаара: фронтальные `default` и `alt2`, профиль в обе стороны) - мозаика 6x6.
2. OSD определяет поворот страницы (90/180/270), дальше работа идёт на выпрямленной копии,
   результат поворачивается назад без потерь.
2a. **QR и штрихкоды** (`codes.py`): `cv2.QRCodeDetector` и `cv2.barcode.BarcodeDetector`
   (есть в `opencv-python-headless` 4.x, новых зависимостей нет; штрихкоды ищутся в трёх
   масштабах, детектор чувствителен к ширине штриха). Сначала находится рамка, потом
   расшифровка: не расшифрованный код закрашивается так же. Рамка с полем 8 %.
3. OCR (картинка до 2000 px по длинной стороне увеличивается до 3 раз, свыше 4000 px
   уменьшается; автоконтраст). Слова склеиваются: строки через `\n`, блоки через пустую строку.
4. Детектор запускается на всём тексте и построчно (разные контексты NER). Слово закрашивается,
   если пересекает находку.
5. **Низкая уверенность OCR** (< 40): слово не проверить, поэтому оно закрашивается целиком,
   если в нём есть цифра или >= 3 букв/цифр. Размытый и плохо читаемый текст исчезает целиком.
   Решение осознанно консервативное, отказа «слишком много неуверенного текста» нет: закраска
   и так скрывает такой текст. Прозрачного пересчёта нет - счётчик `low_conf_boxes`.
5a. **Нераспознанный текст** (`unreadable.py`, `MEDIA_MASKER_HIDE_UNREADABLE`, по умолчанию
   включено): на первом проходе ищутся тонкие штрихи (blackhat/tophat по контрасту >= 40),
   склеиваются в области; отбрасываются области под распознанными словами и кодами, слишком
   маленькие/большие, вытянутые линии (> 18:1) и заливки (плотность штрихов вне 3-55 %).
   Остальное закрашивается и даёт `hidden_text`. Если кандидаты занимают > 20 % картинки, это
   фото или текстура: ничего не закрашивается (иначе фото товара почернело бы целиком).
6. После закраски страница читается заново; если находки остались - закраска повторяется
   (до 3 проходов), затем 422 `pii_remains_after_masking`. Чистая картинка стоит одного OCR.

## Что НЕ закрашивается (ограничения)

- Рукопись и нераспознанный текст закрашиваются только эвристикой: она пропускает письмо
  без контраста со стороны фона, слитое с рисунком, и всё на фото, где кандидатов > 20 %
  площади (срабатывает защита от закраски всего кадра). Рукопись, прочитанная OCR как слово
  с уверенностью >= 40, не закрашивается и уходит в текст как есть.
- Адреса детектор `pseudonymizer` не ловит (типа ADDRESS в нём нет): адрес на визитке
  остаётся в тексте и картинке открытым, как и в обычном тексте запроса.
- Текст под большим углом (> ~30 градусов, кроме кратных 90), на сложном фоне, очень мелкий.
- Содержимое кодов, не похожих на vCard/MECARD (ссылка с идентификатором, свободный текст):
  идёт в текст как есть, и токенами становится только то, что нашёл детектор. Логотипы,
  узнаваемые без текста объекты.
- Лица, которые Хаара не находит (сильный наклон, закрытое, маленькое, не в анфас/профиль).
- Имена без контекста там, где NER Natasha их не видит (редкие, слитные, на латинице без
  признаков).
Это пределы подхода «OCR + детектор текста», а не гарантия анонимности картинки.

## Переменные окружения

См. `deploy/media-masker.env.example`; `MEDIA_MASKER_HIDE_UNREADABLE` (`true`/`false`)
включает закраску нераспознанного текста. Пределы (константы в `config.py`): файл 32 МБ,
картинка 50 Мп; страниц PDF - `MEDIA_MASKER_MAX_PDF_PAGES` (20), параллельных запросов -
`MEDIA_MASKER_MAX_CONCURRENCY` (2).

## Время и память (замер 04.11.2026, 2 ядра, CPU без GPU)

| Случай | Время | Память |
|---|---|---|
| старт (Natasha + каскады) | 0,9 с | 260 МБ RSS |
| фото 1600x1200, текст и лицо, 4 закраски | 2,4 с | сервис пик 281 МБ, tesseract до ~340 МБ |
| PDF-скан 5 страниц 1200x500 | 8,5 с | процесс пик 340 МБ |
| PDF-скан 5 страниц A4 (300 dpi, 30 строк) | 19 с | процесс пик 456 МБ + tesseract |

Страница с ПДн стоит два OCR (проверка после закраски) и OSD (~0,6 с). Клиент ждёт ответа
`MEDIA_MASKER_TIMEOUT_MS` (120 с у pii-proxy); 20 страниц A4 укладываются примерно в 80 с.
`deploy/media-masker.service.template`: `MemoryMax=2G` (tesseract - дочерний процесс того же
cgroup). Журнал JSON без содержимого (`jsonlog.py`): события `media_masked` и `media_refused`
несут только счётчики и код причины.
