# Рой на Codex (подписка ChatGPT)

[English version](codex-harness.md)

**Харнес** — программа, в которой живут агенты. LabOps поддерживает два:

| Харнес | На чём работает агент | Чем оплачивается |
|---|---|---|
| `claude` (по умолчанию) | Claude Code | ваша подписка Claude (Max/Pro) |
| `codex` | Codex CLI | ваша подписка ChatGPT |

Всё остальное не меняется: рабочая папка агента и его память, общий second-brain,
Telegram-бот, watchdog под systemd, доска задач, маскирование ПДн.

Здесь простыми словами описано, что меняется, если выбрать `codex`.

---

## 1. Один харнес на весь рой

- Харнес — **первый вопрос установщика**: `Харнес роя (claude / codex) [claude]`.
  Чтобы ответить без вопроса, задайте `HARNESS=claude` или `HARNESS=codex`
  (`HARNESS=codex bash install.sh`). При `NONINTERACTIVE=1` без `HARNESS` выбирается `claude`.
- Выбор записывается в `~/.claude-lab/shared/swarm.env` (`HARNESS=codex`, права `600`), и все
  скрипты читают его оттуда. Нет файла или строки `HARNESS` — значит `claude`: рои, поставленные
  до появления выбора, работают без миграции.
- **Все агенты роя на одном харнесе.** Смешанного роя нет. Новые агенты (`create-agent` /
  `new-agent.sh`) наследуют харнес и о нём не спрашивают.
- **Сменить харнес у существующего роя установщиком нельзя.** Если агенты уже есть, а
  `install.sh` запущен с другим харнесом, он остановится и объяснит почему.

## 2. Что делает установщик на `codex`

1. **Проверяет сеть**: должны открываться `github.com` (пакет Codex), `chatgpt.com` (туда идёт
   весь трафик агента к модели) и `auth.openai.com` (вход).
2. **Ставит Codex CLI закреплённой версии `0.171.0`.** Скачивает официальный пакет релиза с
   `github.com/openai/codex/releases`, сверяет sha256 и распаковывает в
   `~/.local/share/labops-codex/0.171.0/` пользователя агентов, со ссылкой `~/.local/bin/codex`.
   Node.js не нужен. В `/usr/local/bin` ничего не кладётся. Старые версии не удаляются: на них
   могут работать запущенные агенты.
   Версия закреплена, потому что Telegram-драйвер опирается на протокол `codex app-server`
   именно этой версии; новая версия Codex принимается только вместе с проверкой драйвера и
   новыми контрольными суммами. Поддерживается Linux x86_64 и aarch64.
3. **Ставит маскирование ПДн — на Codex оно обязательно.** В рое на Codex `SKIP_PII_PROXY=1`
   не принимается, а если сервис маскирования не ставится, установка останавливается. См. раздел 5.
4. **Входит в ChatGPT за весь рой** (раздел 3).
5. **Спрашивает модель.** По умолчанию у агентов на Codex — **`gpt-6.2-sol`**. Модель
   записывается в `config.toml` агента (`model = ...`). Настройки модели — зона оператора:
   без владельца не менять.
6. Ставит Telegram-канал (`tg-plugin`) **без** Claude Code и без его хуков — на Codex они не
   нужны.
7. Создаёт первого агента (Developer), как и на Claude.

`bash install.sh --no-agent` готовит машину — включая сервис маскирования ПДн хоста и каталог
общего входа `~/.claude-lab/shared/codex` (права 700) — и вместо создания агента печатает команду
входа и команду `new-agent.sh`. Повторный запуск установщика от root (в том числе с
`NONINTERACTIVE=1`) находит уже выбранный харнес в рое пользователя агентов (`AGENT_OS_USER` —
указать пользователя явно) и не подменяет его умолчанием `claude`.

## 3. Вход: один вход в ChatGPT на весь рой

Все агенты пользуются **одним** входом. Он лежит в общей папке:

```bash
CODEX_HOME=~/.claude-lab/shared/codex codex login --device-auth
```

Установщик запускает эту команду сам (Enter на вопросе). Codex покажет ссылку и код. Откройте
ссылку на любом устройстве (телефон, ноутбук — браузер на сервере не нужен), войдите в аккаунт
ChatGPT, подписку которого будет тратить рой, и введите код.

- Войти позже: введите `s` на вопросе или запустите установщик с `SKIP_CODEX_LOGIN=1`. Агент
  создастся, но отвечать не будет, пока вы не выполните команду выше. Перезапускать потом
  ничего не нужно: watchdog заметит вход и сам поднимет агента.
- Принимается только вход **по подписке ChatGPT**. Codex, вошедший по API-ключу OpenAI,
  считается невошедшим (оплата шла бы мимо подписки).
- У каждого агента свой `CODEX_HOME` = `~/.claude-lab/<агент>/.codex/`. В нём `auth.json`,
  `auth.json.lock` и `auth.lock` — **ссылки** на общую папку. Когда любой агент обновляет
  токен, новый токен пишется сквозь ссылку и виден остальным; общие файлы блокировки не дают
  двум агентам обновлять токен одновременно. Раздельные копии ломали бы друг друга при каждом
  обновлении — поэтому вход общий.
- Если у агента уже был свой `auth.json`, он переносится в общую папку (если там ещё пусто) или
  откладывается как `auth.json.bak-<время>`.

Проверить вход в любой момент:

```bash
CODEX_HOME=~/.claude-lab/shared/codex ~/.local/bin/codex login status   # "Logged in using ChatGPT"
```

## 4. Файлы агента на Codex

| Путь | Что это |
|---|---|
| `~/.claude-lab/<агент>/.claude/` | рабочая папка агента, как у Claude: память, хуки, скрипты, секреты, плагин канала |
| `~/.claude-lab/<агент>/.claude/AGENTS.md` | идентичность агента для Codex. Собирается из `AGENTS.src.md` (те же тексты, что в `CLAUDE.md`, с вариантом раздела о канале для Codex). Codex не умеет `@`-импорт, поэтому драйвер пересобирает `AGENTS.md` перед каждой новой нитью — память в нём всегда свежая. Правьте исходник и файлы памяти, а не `AGENTS.md` |
| `~/.claude-lab/<агент>/.codex/` | `CODEX_HOME` агента (права `700`): `config.toml`, общие правила `AGENTS.md`, `rules/`, нити Codex, ссылки на общий вход |
| `~/.claude-lab/shared/codex/` | общий вход роя в ChatGPT (права `700`) |
| `~/.claude-lab/shared/swarm.env` | `HARNESS=codex` |

В `config.toml` (права `600`):

- `model` — модель (по умолчанию `gpt-6.2-sol`);
- `model_provider = "labops-pii"` — **все запросы к модели идут через локальный pii-proxy
  агента** (`http://127.0.0.1:<порт>/backend-api/codex`), вход — через ChatGPT;
- `approval_policy = "never"` и `sandbox_mode = "danger-full-access"` — аналог
  `--dangerously-skip-permissions` у Codex (см. [SECURITY.md](../SECURITY.md));
- сжатие запросов выключено — прокси должен прочитать запрос, чтобы замаскировать его;
- MCP-серверы second-brain. Bearer берётся из переменной окружения `AGENT_BEARER` (из
  `agent.env` агента); сам токен в этот файл не пишется.

## 5. Маскирование ПДн обязательно при установке

На Claude pii-proxy включён по умолчанию, но его можно отключить. На Codex — нельзя:

- установщик и `new-agent.sh` отказывают при `SKIP_PII_PROXY=1`;
- прокси агента поднимается **до** рендера его рабочей папки, потому что адрес прокси
  записывается в `config.toml`; не поднялся прокси — агент не создаётся;
- в `config.toml` нет другого пути к модели, кроме прокси.

### Если прокси упал: агент работает напрямую (решение владельца 23.11.2026)

Если pii-proxy агента перестал отвечать, агент **продолжает работать без него**, а не замолкает.
Пока это длится, **персональные данные уходят в модель без маскирования** — владелец этот риск
принимает. Как это устроено:

- watchdog проверяет `/health` прокси раз в ~30 секунд. Три неудачи подряд переводят агента в
  режим «напрямую», две удачи подряд возвращают через прокси (один медленный ответ ничего не
  меняет). Заодно watchdog сам пробует поднять юнит прокси;
- переход напрямую хода не ждёт: драйвер прерывает его (`turn/interrupt`; на мёртвом прокси
  он всё равно бы упал), перезапускает `codex app-server`, продолжает **ту же нить**
  (`thread/resume`) — разговор не теряется — и повторяет вход того же хода. Ход, успевший
  закончиться сам до прерывания, не повторяется; ход, уже упавший на мёртвом прокси,
  повторяется без сообщения об ошибке пользователю. Обратно через прокси — только между ходами.
  Напрямую меняется только адрес провайдера
  (`-c model_providers.labops-pii.base_url="https://chatgpt.com/backend-api/codex"` — тот же
  бэкенд, куда ходит прокси, тот же вход ChatGPT). Сам провайдер не меняется: Codex не даёт
  продолжить нить с другим провайдером;
- агент, который стартует при лежащем прокси, сразу стартует напрямую;
- текущий режим лежит в `~/.claude-lab/<агент>/.claude/state/pii-mode` (`proxy` или `direct`).

Как заметить: в Telegram приходит **одно** сообщение при переходе на прямую работу («pii-proxy
недоступен — работаю напрямую, ПДн без маскирования») и одно — при возврате через прокси.
`/doctor`, пока прокси лежит, показывает то же предупреждение.

На Codex прокси ходит в `https://chatgpt.com`: маскирует запросы OpenAI Responses, которые шлёт
Codex, и возвращает значения в потоковом ответе. Подробнее:
[`pii-proxy/README.md`](../../pii-proxy/README.md).

### Веб-поиск идёт мимо прокси

У Codex свой веб-поиск, отдельный навык поиска агентам на Codex не нужен. Но этот поиск
выполняется внутри chatgpt.com (`codex_apps`), **а не через pii-proxy**: запрос уходит ровно
таким, каким его написала модель. Решение владельца 23.11.2026: поиск оставить, риск принять.
Для страховки в инструкциях агента (`AGENTS.md`) запрещено вставлять в поисковый запрос
персональные данные из разговора. Чтобы выключить поиск у одного агента, добавьте в его
`.codex/config.toml` `web_search = "disabled"` и в раздел `[features]` — `apps = false`
(инструмент поиска приходит из фичи apps), затем перезапустите агента.

## 6. Как работает агент: драйвер

На Claude watchdog запускает в tmux терминальное приложение Claude Code, а Telegram-плагин живёт
внутри него. У Codex печатать некуда. Вместо этого:

```
systemd → watchdog.sh → start-agent.sh → tmux-сессия labops-<агент>
                                            └─ драйвер: процесс tg-plugin (bun, LABOPS_HARNESS=codex)
                                                 └─ codex app-server (JSON-RPC по stdio)
```

- **Драйвер** — тот же процесс `tg-plugin`, но в режиме Codex. Это главный процесс агента:
  он читает Telegram, запускает `codex app-server` своим дочерним процессом и общается с ним по
  JSON-RPC. tmux только держит процесс: ничего не печатается на экран и ничего не читается с
  экрана, поэтому нет целого класса проблем вроде «залипшего ввода».
  `tmux attach -t '=labops-<агент>'` показывает журнал драйвера.
- Инструменты канала (`reply`, реакции, отправка файлов, скачивание вложений, …) отдаются Codex
  по MCP на внутреннем порту плагина (`127.0.0.1:6000+`, путь `/mcp`) и защищены случайным
  токеном, который меняется при каждом старте.
- **Одна долгая нить.** Драйвер держит у агента одну нить Codex — как одну длинную сессию
  Claude. Её id сохраняется; после перезапуска драйвер продолжает ту же нить и только если не
  получилось — начинает новую.
- **Одна очередь на все входы.** Сообщения Telegram, задачи с доски / от agent router и
  доставки через webhook попадают в одну очередь. Агент свободен — сообщение начинает новый ход.
  Ход уже идёт и сообщение из того же чата — оно добавляется в текущий ход (как дописка
  человека в идущий разговор); сообщение из другого чата ждёт конца хода. Задачи с доски
  приходят файлами в `state/codex-inbox/` рабочей папки; файл удаляется только после того, как
  драйвер его принял, поэтому сбой даст повтор, а не потерю задачи.
- **Реакции и прогресс.** 👀 — сообщение взято в работу, 👌 — ход закончен. Живой статус
  прогресса в Telegram строится из событий app-server тем же кодом, что и на Claude.
- **Ответ.** Финальное сообщение агента в конце хода само уходит в чат, который начал ход —
  вызывать `reply` агенту не нужно. `reply` нужен для промежуточных сообщений и файлов; текст,
  уже отправленный через `reply`, не дублируется. Если ход упал, в чат приходит короткое
  предупреждение с ошибкой.
- **Вопросы.** Если Codex спрашивает пользователя, вопрос приходит кнопками в Telegram.
  Запросов подтверждения не ожидается (`approval_policy = never`); если такой придёт, драйвер
  отклонит его и запишет в журнал.
- **Хуки памяти.** На Claude хуки вызывает Claude Code, на Codex — драйвер, и это **те же
  скрипты**: `session-start` (свежая память в первый ход новой нити), `stop` (после каждого
  хода), `precompact`, `heartbeat` (на событиях и раз в минуту в простое) и `brain-flush` (при
  остановке драйвера и перед `/reset`). При перезапуске у драйвера есть до ~30 с, чтобы
  сохранить память в second-brain.
- Токены Telegram, webhook, голоса и поддержки убираются из окружения, которое получает Codex:
  команды, которые запускает модель, их не прочитают.
- Отдельные сессии на каждого человека (`multichat`) на Codex пока не работают — агент держит
  одну сессию.

### Watchdog на Codex

Watchdog не смотрит на экран. Он проверяет:

- процесс драйвера жив и его порт `6000+` слушается (три промаха подряд → перезапуск);
- heartbeat свежий (старше 5 минут → драйвер завис → перезапуск);
- рой вошёл в ChatGPT. Если нет — оператору приходит **одна** тревога с командой входа, и
  watchdog ждёт, а не перезапускает агента по кругу; как только вход появился, агент
  перезапускается сам;
- pii-proxy отвечает на `/health`. Если нет — агент переходит в режим «напрямую» (раздел 5).

## 7. `/reset` и `/doctor` на Codex

- **`/reset force`** — начать с чистого контекста, память сохраняется. На Codex это делает сам
  плагин: дожидается конца текущего хода, сохраняет память в second-brain, пересобирает
  `AGENTS.md` и начинает новую нить. `/reset` без `force` только просит подтверждения.
- **`/doctor`** — проверить агента и починить, что можно, как на Claude. На Codex проверяет вход
  в ChatGPT, юнит systemd, tmux-сессию, драйвер (процесс, порт, heartbeat — при поломке
  перезапускает), обвязку и second-brain. Если сам плагин лежит, watchdog читает `/doctor` из
  Telegram напрямую.
- **`/stop`** — прервать текущий ход.

## 8. Задачи от других агентов (webhook-listener)

`webhook-listener` выполняет разовые задачи от других агентов. В рое на Codex он запускает
**`codex exec` вместо `claude -p`** — в рабочей папке агента и с `CODEX_HOME` агента, так что
задача идёт на той же модели, через тот же pii-proxy и с тем же доступом к second-brain. Если
прокси не отвечает, задача всё равно выполняется — напрямую (тот же адрес бэкенда, что у
драйвера), а владелец получает предупреждение не чаще раза в час.
`codex exec` со входом через ChatGPT — официально поддерживаемый способ работать по подписке,
поэтому он разрешён; запрет headless `claude -p` остаётся для Claude.

## 9. Если что-то не работает

| Симптом | Что делать |
|---|---|
| В Telegram тревога «Codex не вошёл в ChatGPT» | `CODEX_HOME=~/.claude-lab/shared/codex codex login --device-auth` — один раз на весь рой; агенты поднимутся сами |
| Сообщение «pii-proxy недоступен — работаю напрямую» | агент работает, но ПДн не маскируются. Проверьте `systemctl --user status labops-pii-proxy@<агент>`; когда прокси поднимется, агент сам вернётся через него и сообщит |
| Агент молчит, тревоги нет | пришлите `/doctor`; или `tmux attach -t '=labops-<агент>'` — журнал драйвера |
| Не та версия Codex | `~/.local/bin/codex --version` должен показать `0.171.0`; повторный `install.sh` вернёт её |
| Хочу перевести рой между Claude и Codex | установщик этого не делает; это отдельная процедура по согласованию с владельцем |
