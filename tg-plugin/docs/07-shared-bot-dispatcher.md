# Один бот на нескольких агентов

## Зачем

У каждого пользователя приложения — свой агент со своей памятью. Заводить
каждому отдельного бота нельзя: человек должен просто написать в
`@labops_appbot` и попасть к своему ассистенту, а чужих диалогов не видеть.

## Почему нельзя «просто дать всем один токен»

Приём и отправка в Bot API устроены по-разному:

- **Приём эксклюзивен.** `getUpdates` отдаёт апдейт ровно одному читателю.
  Два агента с одним токеном не «получат каждый своё» — они будут
  выхватывать сообщения друг у друга вперемешку, а Telegram начнёт отвечать
  409 Conflict. Никакой ошибки на стороне пользователя при этом не видно:
  сообщения просто иногда уходят не туда.
- **Отправка не эксклюзивна.** `sendMessage` с общим токеном можно звать
  откуда угодно и сколько угодно.

Отсюда решение: эксклюзивным приёмом занимается один процесс, а отвечают
агенты сами.

## Как это работает

```
человек → @labops_appbot → диспетчер (единственный поллит getUpdates)
                                │  по from.id находит агента
                                ▼
                POST 127.0.0.1:600N/hooks/agent (bearer агента)
                                │
                                ▼
                    сессия агента этого пользователя
                                │  reply-инструмент, тот же токен
                                ▼
                         человек в своём чате
```

Изоляция держится на одной строчке: агент ищется по `from.id`, а не по
чату. В личке это одно и то же, но привязка по чату отдала бы одному
человеку агента другого, если бота добавят в группу.

Дополнительный рубеж — на стороне агента: `/hooks/agent` сверяет `chatId`
со своим `allowed_chat_ids`, поэтому ошибка в таблице маршрутов приводит к
403, а не к чужой переписке.

## Что настроить

1. **Агенты за диспетчером** — `ingress: "external"` в `config.json`
   (или `TELEGRAM_INGRESS=external` в `channel.env`). В этом режиме агент
   не поднимает свой поллер, но продолжает отвечать. По умолчанию режим
   `poll` — агенты со своими ботами не затрагиваются.
2. **Диспетчер** — юнит из `examples/telegram-dispatcher.service.example`,
   окружение из `examples/dispatcher.env.example`. Токен общего бота живёт
   только в `EnvironmentFile` с правами 600.
3. **Таблица маршрутов** — `routes.json` рядом с состоянием диспетчера:

   ```json
   { "routes": { "308749463": "labops-app" } }
   ```

   Ключ — telegram id пользователя, значение — идентификатор его агента.
   Файл перечитывается по mtime, поэтому нового пользователя видно без
   рестарта. Битый JSON не обнуляет маршруты: диспетчер продолжает работать
   на последней валидной версии и пишет предупреждение в лог.

## Границы MVP

- Принимается только текст (и подписи к медиа). Вложения требуют скачивания
  общим токеном и передачи файла в воркспейс агента — человеку в ответ
  приходит явное «пока принимаю только текст», а не тишина.
- Агенты с собственными ботами (`developer`, `carmella`) остаются в режиме
  `poll` — переводить их незачем.
