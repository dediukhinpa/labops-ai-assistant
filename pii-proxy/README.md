# pii-proxy

Локальный HTTP-прокси между Claude Code и API модели: маскирует персональные данные в
запросах через сервис псевдонимизации (`labops-pii`, `pii-proxy/docs/pseudonymizer.md`) и возвращает оригиналы в ответах. Один процесс на агента.

## Вложения: PII_PROXY_IMAGE_POLICY

| Значение | Что делает |
|---|---|
| `mask` | по умолчанию. image и PDF base64 уходят в `media-masker` (OCR rus+eng, закраска ПДн, пикселизация лиц) |
| `strip` | блок заменяется текстом-заглушкой |
| `reject` | любое вложение - 422 |
| `passthrough` | как есть, ПДн на картинках уйдут в модель; только по явному решению владельца |

При `mask` обязателен `MEDIA_MASKER_API_TOKEN` (без него прокси не стартует), адрес
`MEDIA_MASKER_URL` (по умолчанию `http://127.0.0.1:8320`), `MEDIA_MASKER_TIMEOUT_MS` (120 с).

Где живёт OCR: отдельный сервис media-masker (`labops_pii.media.mask` из вендоренной `labops-pii`), а не эндпоинт сервиса псевдонимизации. Причины:
Tesseract и растеризация PDF тяжёлые (до 2 ГБ, минуты CPU) и не должны отнимать память и
потоки у текстового сервиса, на котором держится каждый запрос; у юнита свои `MemoryMax` и
очередь (2 параллельных обработки); детектор ПДн при этом тот же `PiiDetector`.

- `image` base64: данные и `media_type` заменяются закрашенной перекодированной картинкой, а
  следом идёт `text`-блок «Текст на изображении (распознан локально, персональные данные
  заменены метками): …» с распознанным текстом, `QR-код: …` / `Штрихкод: …` и, если
  что-то нераспознанное скрыто, пометкой «На изображении есть нераспознанный рукописный текст,
  он скрыт». Блок - обычный лист: тот же тред и `case_labels`, вторая линия `/check`, память
  восстановлений, нумерация токенов по порядку обхода; в ответе модели токены становятся
  настоящими значениями обычным путём. Модель видит `[PERSON_1]`, `[PHONE_1]` и может
  назвать их пользователю. Ничего не распознано - блока нет. `cache_control` картинки
  переносится на этот блок. Для PDF-скана - блок после каждой страницы-картинки.
- Текст блока зависит только от содержимого картинки, поэтому его маска детерминирована (ключ
  кэша маскирования - тред, `boot_id`, режим меток и текст); результат media-masker с текстом
  кэшируется по sha256 картинки, OCR на каждом запросе истории не повторяется. В кэше
  media-masker лежит распознанный текст со значениями (только в памяти прокси, где и так
  проходит каждый запрос целиком); в журнал он не попадает.
- `document` PDF base64: с текстовым слоем - блоками `text` (по странице), которые дальше
  проходят обычное маскирование токенами и вторую линию `/check`; скан - блоками `image`
  с закрашенными страницами (предел страниц в media-masker, 20). `title` документа становится
  первым text-блоком; `cache_control` переносится на последний блок замены.
- Fail closed: не base64 (url, file), не PDF, файл слишком большой или нечитаемый, ПДн остались
  после закраски, таймаут, сбой или недоступность media-masker - вложение НЕ уходит к модели,
  вместо него текст-пометка с причиной из закрытого списка (`not_base64`, `unsupported_type`,
  `too_large`, `too_many_pages`, `unreadable`, `pii_remains`, `refused_other`, `timeout`,
  `service_unavailable`) и просьбой сказать пользователю, что файл скрыт. Запрос не
  отклоняется: иначе вложение в истории ломало бы каждый следующий запрос сессии.
- Журнал: событие `request` несёт `masked_attachments` и `blocked_attachments`
  (`{причина: число}`); значений ПДн и имён файлов нет.
- Отказ по файлу кэшируется, сбой сервиса - нет (после восстановления вложение обработается).
- Результат кэшируется по sha256 данных (бюджет 64 МБ base64, вытеснение давних): картинки
  истории не гоняются через OCR на каждом запросе, байты одинаковы - кэш промпта Anthropic цел.
  После перезапуска прокси кэш пуст, OCR детерминирован, поэтому байты те же.
- Порядок обхода и нумерация токенов не изменились: текст PDF встаёт на место документа.

## Включение и ресурсы

1. Установить Tesseract: с sudo `apt-get install tesseract-ocr tesseract-ocr-rus
   tesseract-ocr-eng tesseract-ocr-osd`; без sudo - `apt-get download` + `dpkg -x` и
   `LD_LIBRARY_PATH`/`TESSDATA_PREFIX` (см. `docs/media-masker.md`).
2. Поднять `media-masker` (unit `MemoryMax=2G`, `OMP_THREAD_LIMIT=1`, 2 параллельных запроса).
3. Задать `MEDIA_MASKER_API_TOKEN` в секретном файле прокси, перезапустить прокси.

`pii-setup.sh host` делает шаги 1-2 сам, если Tesseract (rus+eng) найден: venv, юнит
`labops-media-masker`, токен в `~/.config/labops-pii/media-masker.token` (600); `pii-setup.sh
agent` пишет в env прокси `mask` и токен. Tesseract не найден - громкое предупреждение,
media-masker не ставится, агентам пишется `PII_PROXY_IMAGE_POLICY=strip` (старт не ломается).

Сквозная проверка с настоящим OCR: `pii-proxy/scripts/make_e2e_fixtures.py <каталог>`,
затем `MEDIA_E2E_URL=... MEDIA_E2E_TOKEN=... MEDIA_E2E_DIR=<каталог> bun test
tests/media-e2e.test.ts` (без переменных тест пропускается).

## Остаточные риски

Рукописный текст, который OCR прочитал с уверенностью >= 40 или который не поймала эвристика
закраски (бледный, слитый с рисунком), очень мелкий текст, текст под углом (кроме кратных 90
градусов), сложный фон, логотипы, лица вне работы каскадов Хаара. Распознанный текст теперь
доходит до модели (токенами): что детектор `pseudonymizer` не опознал как ПДн, уйдёт открытым.
Это касается адресов (типа ADDRESS в детекторе нет), ссылок и свободного текста в QR; если
вторая линия `/check` найдёт остаток, лист дозамаскируется (`/remask_batch` сервиса, labops-pii
1.1.0+), а если остаток не ушёл - заменится заглушкой; запрос не отклоняется (в журнале событие
`pii_after_mask_fixed`).
Фото без текста не закрашивается, если эвристика приняла его за фото (кандидатов > 20 % площади);
картинки внутри PDF с текстовым слоем отбрасываются (уходит только текст), но ПДн, набранные в картинке такого PDF, не читаются.
Подробности - `docs/media-masker.md`. Лица без текста и имена без контекста NER может пропустить.

## Установка (обычно делает `agent-architecture`)

- `install.sh` ставит сервис псевдонимизации: `agent-architecture/orchestration/pii-setup.sh host`.
- `new-agent.sh` на каждого агента: `pii-setup.sh agent <id>`. Создаёт `secrets/pii-proxy.env`
  (образец: `deploy/env.example`), user-юнит `labops-pii-proxy@<id>`, прописывает
  `ANTHROPIC_BASE_URL` и хук `hooks/session-end.sh` в `settings.json` агента.
- Порты: `6300 + индекс агента` (webhook плагина - 6000+, listener - 6100/6101).
- Отключить: `SKIP_PII_PROXY=1` (ПДн тогда уходят в модель немаскированными).

## Проверка живости

`GET /health` (без авторизации, прокси слушает только `127.0.0.1`) отвечает `{"status":"ok"}`.
По нему `watchdog.sh` решает, можно ли запускать `claude`.

## Проба квоты и отказы upstream

Первый запрос каждой сессии claude под подпиской - служебная проба квоты (`max_tokens` 1, один
user-текст `quota`, без `system`). Маскировать в ней нечего, поэтому прокси пересылает её без
изменений. Раньше маскер дописывал в неё `system`-вставку про токены, и именно эта проба (одна
на сессию, `masked_leaves: 1`) получала 429, а все остальные запросы шли с 200; единственное
отличие пробы от обычных запросов - то, что у неё нет собственного `system` claude. В журнале
проба теперь - обычное событие `request` с `masked_leaves: 0`; если 429 останется, событие
`upstream_error` покажет, чей он.

Любой не-2xx ответ upstream доходит клиенту как есть, а в журнал пишется событие `upstream_error`:
`status`, `probe` (был ли это запрос-проба), `upstream_error_type` (`error.type` из тела, например
`rate_limit_error`) и `upstream_headers` (только `request-id`, `retry-after`, `x-should-retry`,
`anthropic-ratelimit-*`). Тела ответа и текстов запроса в журнале нет. По событию видно, чей это
отказ: честный лимит Anthropic (есть `retry-after` и заголовки лимитов) или отказ из-за формы
запроса.

## Застрявшая сессия

После `STUCK_FAILURE_THRESHOLD` (3) отказов 422/503 подряд в одной сессии прокси пишет событие
`session_stuck` (отпечаток сессии, счётчик, код; значений ПДн нет), не чаще раза в час на сессию.
Если задан `PII_PROXY_ALERT_FILE`, строка JSON дописывается туда; `watchdog.sh` читает файл и
шлёт оператору алерт через `notify.sh`.
